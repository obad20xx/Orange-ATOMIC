## 🚀 Milestones & Copilot Integration Blueprint

### Milestone 1: Application Foundation & Local Orchestration

**Goal:** Build the "Tasky" application features, ensure clean frontend-backend REST communication, integrate HashiCorp Vault, and orchestrate locally using Docker Compose.

#### Task 1.1: Database Schema & Spring Boot Entities

* **Details:** Define a `Task` entity with audit fields tracking state changes: `id`, `title`, `description`, `status` (ENUM), `createdBy`, and `lastModifiedBy`.
* **Copilot Context:** Open your blank project in VS Code with `pom.xml` open in a split tab.
* **Copilot Prompt:**
> Create a JPA Entity named `Task` for a PostgreSQL database. Include fields for ID (Autogenerated UUID or Long), title (String), description (String), status (Enum: TODO, IN_PROGRESS, DONE), createdBy (String), and lastModifiedBy (String). Use Lombok annotations (`@Data`, `@NoArgsConstructor`, `@AllArgsConstructor`, `@Builder`) to reduce boilerplate. Add Jakarta Validation annotations to ensure title and status cannot be blank or null.



#### Task 1.2: Business Logic & The Core Endpoints

* **Details:** Implement the Controller layer. The main challenge requirement is a `GET /infos` endpoint that calls Vault. We will also build a clean `/api/tasks` REST CRUD interface to show your application development mastery.
* **Copilot Context:** Open a new file `TaskController.java`.
* **Copilot Prompt:**
> Write a REST Controller using Spring Boot 3 handling `/api/tasks`. Use constructor injection for the service layer. Implement endpoints for GET (all tasks), POST (create task), and PUT (update task status, capturing who modified it). Ensure request bodies are verified using `@Valid`.


* **Task 1.2.1: The Vault Integration (`GET /infos`)**
* **Copilot Prompt:**
> Create a REST Controller mapping `GET /infos`. This endpoint must call an injected `VaultService` that retrieves system health metadata or application configurations from HashiCorp Vault's `/v1/sys/health` endpoint using standard Spring `RestClient`. Wrap the logic with a Resilience4j `@CircuitBreaker` annotation. If Vault is down, return a graceful fallback JSON payload stating "Vault service unavailable" instead of a 500 error.



#### Task 1.3: Robust I/O Validation & Error Handling

* **Details:** Implement clean error handling to catch bad inputs or database tracking failures.
* **Copilot Prompt:**
> Create a class named `GlobalExceptionHandler` annotated with `@ControllerAdvice`. Write exception handler methods that catch `MethodArgumentNotValidException` (validation errors) and return a clean, structured JSON payload containing timestamp, HTTP status code, and a clean map of field errors.



#### Task 1.4: Multi-Stage Containerization (`Dockerfiles`)

* **Details:** Write production-ready Dockerfiles targeting the WSL2 container environment.
* **Copilot Prompt for `ATOMIC-Backend/Dockerfile`:**
> Create a multi-stage, production-grade Dockerfile for this Spring Boot application. Stage 1 uses `maven:3.9-eclipse-temurin-21-alpine` to cache dependencies and build the application executable. Stage 2 uses `eclipse-temurin:21-jre-alpine`, sets up a non-root system user named 'taskyuser', exposes port 8080, and runs the application as that user.


* **Copilot Prompt for `ATOMIC-Frontend/Dockerfile`:**
> Create a multi-stage Dockerfile for a Vue 3 application built with Vite. Stage 1 uses `node:20-alpine` to install dependencies and run `npm run build`. Stage 2 uses `nginx:alpine`, copies the production build output to the nginx html directory, replaces the default nginx config with a custom setup that supports single-page application routing, and runs as a non-root user.



#### Task 1.5: Unified Local Orchestration (`docker-compose.yml`)

* **Details:** Stitch the complete ecosystem together in the project root.
* **Copilot Prompt:**
> Write a `docker-compose.yml` file combining four services: `tasky-frontend` (context: ./ATOMIC-Frontend), `tasky-backend` (context: ./ATOMIC-Backend), a PostgreSQL 15 database instance, and a HashiCorp Vault service. Include internal container healthchecks for PostgreSQL and Vault. The backend must have a `depends_on` rule specifying that it should only start once both postgres and vault pass their respective healthchecks.

**Goal:** Translate the verified Docker Compose setup into a modular, production-ready Helm chart.

#### Task 2.1: Helm Chart Initialization

#### Task 2.2: Externalize Upstream Chart Dependencies

* **Copilot Prompt:**

#### Task 2.3: App Configs, Secrets, and Hardening Templates

* **Details:** Construct your application deployment manifests with integrated resource constraints and configurations.
* **Copilot Prompt for `templates/backend-deployment.yaml`:**
> Write a Kubernetes Deployment template for the Tasky Spring Boot backend. Ensure it includes: livenessProbe and readinessProbe targeting the Spring Boot Actuator endpoint `/actuator/health`, secure environment variables populated from a Kubernetes Secret (for the database password), explicit resource limits (100m CPU, 512Mi RAM), and a securityContext blocking root execution.

### Milestone 3: Home Lab Edge Networking (Day 4)

**Goal:** Utilize your static home IP address to safely expose the Tasky application to the public internet, showcasing elite platform skills.

#### Task 3.1: Automated K8s Control Plane Bootstrapping

* **Details:** Use `k3d` or `kind` inside WSL2 to spin up a local node mapping edge ingress paths directly to your Windows host.
* **Copilot Prompt (`scripts/bootstrap.sh`):**
> Write a bash script to create a k3d cluster named 'tasky-cluster'. Configure the cluster creation to map ports 80 and 443 from the host machine to the k3d load balancer. The script must also apply the official NGINX Ingress Controller installation via Helm.



#### Task 3.2: Edge Configuration & TLS Automation

* **Details:** Map public traffic coming through your home router's forwarded ports (80/443) directly into your app with automated Let's Encrypt certificates via Cert-Manager.
* **Copilot Prompt for `templates/ingress.yaml`:**
> Create a Kubernetes Ingress resource configuration using the NGINX ingress class. Route traffic arriving at your public domain root '/' to the frontend service, and prefix paths matching '/api/' or '/infos' directly to the backend service. Add annotations for cert-manager.io/cluster-issuer: "letsencrypt-prod" to automatically provision trusted TLS certificates.
